# Acompanhamento da integração real

Todos os itens estão pendentes. As telas e os testes existentes do protótipo não concluem releases do sistema hospedeiro.

A fonte canônica do status das fases R1–R8 é `integration/implementation-plan.json`. Este arquivo registra evidências e decisões; não manter uma segunda tabela de status. R0 é registrada abaixo como preparação. Ao retomar, confrontar o plano com o código real antes de iniciar outra fase.

## Modelo de registro por release

Copiar este bloco para cada entrega, sem preencher resultados presumidos:

- Release / ID canônico:
- Data e responsável:
- Repositório hospedeiro / branch / commit ou PR:
- Escopo efetivamente entregue:
- Diretórios frontend e backend:
- Entidades reutilizadas e mapeamento de IDs:
- Endpoints / comandos e permissões:
- Coleções, índices e migrations:
- Flags/capacidades e workspace piloto:
- Testes executados e resultados / links de evidência:
- Validação funcional e responsável autenticado:
- Decisões e desvios do plano:
- Pendências ou bloqueios:
- Procedimento de reversão validado:
- Próxima release com dependências satisfeitas:

Só marcar a fase como concluída após persistência real, testes e critérios de aceite atendidos. Se houver escopo parcial, registrar o que falta e manter a fase em andamento; não usar a existência do protótipo como evidência de integração.
